## Implemented contract

`NativeRankReader::open` now classifies canonical manifests before a native
rank image can enter the upload boundary:

- non-production fixture schemas remain usable by bounded unit proofs;
- an unknown future `glmaxx.rank-manifest.*` schema fails closed;
- production schema `glmaxx.rank-manifest.v0.2.2` is deserialized through
  `deny_unknown_fields` at every object level;
- the production manifest is restricted to the currently specified
  `capacity-exl3` / `capacity-exl3-v0` profile. No unreviewed hybrid or NVFP4
  production-manifest contract was invented;
- pinned repository, model and EXL3 revisions, index and source-manifest
  digests, conversion repository, toolchains, kernel ABI, review token,
  profile identities, and header identities are checked;
- the exact 92-entry source hash map is checked, including all nested required
  file hashes, safe basename syntax, and a lower bound on verified source
  bytes;
- the tokenizer bundle is independently rederived with the same domain
  separator and ordered component preimage used by the converter;
- each manifest tensor is compared with the native descriptor and name for
  identity, role, layer/expert, codec, dtype, TP axis, rank/padded shape,
  flags, physical bytes, quantization group, codec-metadata digest, and
  collective;
- replicated, contiguous-TP, and explicit EXL3 source bindings independently
  derive global/rank/source geometry and rank-specific paths;
- reconstruction policy is codec-specific, and the exact canonical tensor
  array is rehashed into the rank-specific tensor-contract digest; and
- cross-rank validation requires all process-common production identities but
  deliberately does not equate rank-specific tensor-contract digests.

The operational `native-rank-proof` command now requires production manifests,
matches their operation-manifest digest to the current binary, requires the
exact 59,585-tensor capacity inventory, and emits each rank-specific tensor
contract plus the common profile and operation identities.

## Adversarial CPU coverage

The new tests prove:

- a valid typed production manifest binds to its header and descriptor;
- a re-signed false global shape or role still fails;
- unknown nested fields and unreviewed profile names fail;
- future production schemas fail while explicit test schemas remain usable;
  and
- the validator accepts source binding, global geometry, reconstruction, and
  physical-byte arithmetic for every tensor generated by the actual
  59,585-tensor rank plans at ranks 0 and 3.

or checkpoint-load transaction r2 design. It does not validate an externally
stored complete four-rank conversion, allocate pinned memory or HBM, upload a
weight, create a CUDA context, launch a kernel, adopt a rank arena, or reach
healthy model startup. It establishes neither model quality nor performance.
