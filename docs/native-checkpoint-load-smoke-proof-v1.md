# Native TP4 checkpoint-load smoke proof v1

Date: 2026-07-30

Candidate: `da2aa9cccba6116a803a6d5db4b54e6f3ac37c71`

Status: `CPU_AND_HOST_PROOF_COMPLETE_SM120_RUN_PENDING_AUTHORIZATION`

## Scope

This candidate turns the reviewed one-call native checkpoint composition into
a reproducible SM120 command. It does not claim a cn4 load, checkpoint
execution, or serving result. The command can publish its pass record only
after all four rank arenas have been globally adopted, fully verified, then
released with four rank-exact cleanup acknowledgements.

The command is:

```text
glmaxx gpu-checkpoint-load-smoke \
  <external-rank-set-dir> \
  <completed-profile-budget-v0.json> \
  <empty-external-evidence-dir> \
  [phase-timeout-seconds]
```

The operator wrapper is
`scripts/cn4-checkpoint-load-smoke.sh`. It refuses to pass its first line
without a renewed `checkpoint-load-authorized` operator value.

## Host preflight

Before native rank startup, the Rust command:

1. requires an empty evidence directory outside Git;
2. requires the native checkpoint directory outside Git and containing
   exactly `rank-0.g5n` through `rank-3.g5n`;
3. opens and cross-validates the four production rank manifests without
   allocating a CUDA arena;
4. parses the supplied profile budget with `deny_unknown_fields`;
5. requires `measurement_status=complete`, `conversion_allowed=true`, no
   unmeasured blockers, four exact ranks, the frozen 1M/DCP4/MTP6 capacity
   arithmetic, and a measured post-context fit on every rank;
6. reconstructs and independently validates one
   `glmaxx.system-memory-plan.v2` from that budget;
7. derives the memory-plan SHA-256 from the validated canonical pretty-JSON
   bytes, including its final newline;
8. requires every rank manifest to bind the exact supplied profile-budget
   digest and the operation manifest generated by the running binary;
9. requires the rank files to bind the compiled capacity-EXL3 weight policy;
10. validates the linked NVFP4 and EXL3 ABIs and exact workspace formulae,
    then derives one process-common codec-capability digest; and
11. hashes the running executable and uses that digest as the rank-load
    software provenance.

`SystemMemoryPlan::validate` reconstructs the full plan from its own public
rank fields and rejects any change to the rank set, profile, cache layout,
term arithmetic, aggregate, minimum headroom, or admitted slots. The native
startup API accepts the typed plan, not an unrelated caller-provided
memory-plan digest or a caller-provided minimum-free value.

## Live HBM gate

The native ABI adds:

```text
glmaxx_device_memory_info(free_memory_bytes, total_memory_bytes)
```

This is an owner-thread wrapper around `cudaMemGetInfo`. Immediately before
its prepare allocation, each persistent rank:

- verifies the call is made by the context owner;
- requires nonzero free bytes;
- requires the returned total to equal that rank's bound device identity;
- requires free bytes not to exceed total bytes; and
- rejects the common load if live free bytes are less than that rank's exact
  validated `required_bytes`.

This is a pre-allocation gate. It neither changes the memory plan nor treats
aggregate four-GPU free memory as proof that every rank fits.

## Transaction and teardown

The existing prepare, acknowledge, adopt, and finalize phases remain one
exclusive TP4 transaction. This candidate adds an explicit normal teardown:

```text
resident rank set
  -> one common plan/attempt-bound cleanup command
  -> rank 0/1/2/3 owner-thread synchronization and release
  -> four exact cleanup acknowledgements
  -> worker generation retired
```

Success and failure both retire the worker generation. A cleanup
acknowledgement must match rank, plan SHA-256, load-attempt generation, and
owner-allocation generation. Missing, duplicate, malformed, timed-out, or
rank-local cleanup failure cannot be converted into success.

`LoadedNativeCheckpoint::shutdown` consumes the loaded owner, obtains the four
acknowledgements, drops the pool, and joins the dispatcher and four persistent
rank threads before returning. The CLI writes `summary.json` only after this
method succeeds.

Two CPU fault tests prove:

- successful normal teardown returns four exact acknowledgements, releases
  every resident mock arena exactly once, and retires the generation; and
- a cleanup failure at each of ranks 0 through 3 is rank-exact, retains no
  forged acknowledgement for that rank, and is terminal.

The prior failure matrix continues to cover prepare, acknowledge, finalize,
abort, timeout, identity, saturation, and worker-startup failure.

## Success record

On success, `summary.json` binds:

- source commit and running executable SHA-256;
- canonical external rank-set and profile-budget paths;
- profile-budget, system-memory-plan, operation-manifest, codec-capability,
  and rank-set plan digests;
- conversion UUID, tensor count, staging geometry, load attempt, adopted-set
  receipt, and phase/total elapsed time;
- every worker-observed device identity;
- per-rank file, manifest, descriptor, payload, tensor-contract, and arena
  identities and byte counts;
- each rank's required HBM bytes, owner generation, verification-evidence
  digest, verified file bytes, uploaded plane bytes, finalize receipt, and
  cleanup acknowledgement; and
- explicit `full_payload_sha256_verified=true`,
  `full_arena_readback_verified=true`, and
  `model_kernel_launched=false`.

The wrapper independently requires the pass verdict, four cleanup booleans,
no surviving CUDA process, and an unchanged source tree. It records before
and after GPU inventory, topology, source/toolchains/container/CUTLASS
identity, rank-file stat identities, the completed budget hash, build logs,
native symbols, command output, and final artifact hashes. It does not add a
second 326-GiB checkpoint read merely to reproduce hashes already proven by
the typed four-rank loader.

## Explicit exclusions

No cn4 access or GPU work occurred for this proof. The CUDA translation unit
containing `cudaMemGetInfo` has not yet been compiled at this candidate, the
new symbol has not been linked, and no native checkpoint has been loaded.

The checked-in `profiles/profile-budget-v0.json` remains deliberately
incomplete and cannot pass this command. Qualification requires the exact
external completed budget already bound into the four converted rank files.
If no such matching artifact exists, the command correctly blocks rather
than inventing a memory-plan identity.

This smoke loads and releases weights only. It launches CUDA allocation,
zeroing, H2D, D2H, stream, event, and synchronization operations but no model
execution kernel. It does not prove a target layer, logits, MTP, collectives,
KV residency, serving, quality, or performance.

A permanently wedged native call can still make Rust thread joining
unbounded after the phase timeout. The wrapper and evidence contract do not
misstate the Rust timeout as a force-kill mechanism.
